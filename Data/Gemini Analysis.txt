### 1. Zod Validation Schema
This schema should be used in your `auth.controller.js` to validate the profile before sending it to the frontend. It specifically targets the context needed for **Gate Counters** and **Stock Counters**.

```typescript
import { z } from "zod";

export const AuthMeResponseSchema = z.object({
  id: z.string().uuid(),
  email: z.string().email(),
  role: z.object({
    name: z.string(),
    level: z.enum(["SUPER_ADMIN", "MARKET_ADMIN", "VENDOR", "GATE_STAFF", "STOCK_STAFF"]),
  }),
  context: z.object({
    marketId: z.string().uuid(),
    marketName: z.string(),
    // Staff/Vendor Specifics
    assignedShopId: z.string().uuid().nullable(),
    assignedShopName: z.string().nullable(),
    assignedGateId: z.string().uuid().nullable(),    // For Gate Entry tracking
    assignedCounterId: z.string().uuid().nullable(), // For Stock verification
    assignedSectionId: z.string().uuid().nullable(), 
  }),
  kycStatus: z.enum(["NOT_SUBMITTED", "PENDING", "VERIFIED", "REJECTED"]),
});
```

### 2. Prisma Model Update (Migration)
If your current `schema.prisma` doesn't explicitly link staff users to physical gates, you should add a `StaffAssignment` model. This allows the `Auth/me` call to return the **Gate ID** or **Counter ID** without guessing.

```prisma
// Update your prisma/schema.prisma
model StaffAssignment {
  id               String   @id @default(uuid())
  userId           String   @unique
  user             User     @relation(fields: [userId], references: [id])
  marketId         String
  market           Market   @relation(fields: [marketId], references: [id])
  
  // Physical Post Assignments
  assignedGateId   String?  // Links to MarketGate model
  assignedCounterId String? // Links to StockCounter model
  assignedSectionId String? // Links to MarketSection model
  
  status           AssignmentStatus @default(ACTIVE)
  updatedAt        DateTime @updatedAt
}

enum AssignmentStatus {
  ACTIVE
  INACTIVE
  ON_LEAVE
}
```

### 3. Implementation in the Auth Controller
In your [MarketMasterApi controller](https://github.com/oits-dhaka/MarketMasterApi/tree/MME-177-invoice-generation-api), update the `getMe` logic to include these relations:

```javascript
const getMe = async (req, res) => {
  const user = await prisma.user.findUnique({
    where: { id: req.user.id },
    include: {
      role: true,
      stakeholder: {
        include: {
          vendor: { include: { stalls: true } }, // To get shopName/shopId
          staffAssignment: true                  // To get gate/counter context
        }
      }
    }
  });

  // Map the Prisma result to the Zod-validated context
  const context = {
    marketId: user.marketId,
    assignedShopId: user.stakeholder?.vendor?.stalls[0]?.shopId || null,
    assignedShopName: user.stakeholder?.vendor?.stalls[0]?.displayName || null,
    assignedGateId: user.stakeholder?.staffAssignment?.assignedGateId || null,
    assignedCounterId: user.stakeholder?.staffAssignment?.assignedCounterId || null,
  };

  res.status(200).json({ success: true, data: { ...user, context } });
};
```
